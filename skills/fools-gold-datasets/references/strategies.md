# Alternative strategies and when to try them

Use a small controlled comparison when a bottleneck persists. Keep the same semantic content and task contract while comparing methods; change one important variable at a time. These are options, not claims that every route has been validated on this host.

| Strategy | Useful when | Tradeoff / proof needed |
| --- | --- | --- |
| Semantic model → several renderers | Need consistent labels and genuine producer diversity | Independent semantic check required; shared authoring bugs affect every output |
| Full Typst/LaTeX document | Dense technical prose, math, footnotes and pagination dominate | Verify actual fonts, text encoding, accessibility and target resemblance |
| Native DOCX/ODT + Office equations | Office extraction/editability is the target | Save/reopen/export tests; equation support varies by library/exporter |
| Semantic HTML/CSS + MathML | Web-origin documents, flexible layout and fast previews | Test print pagination, font loading and browser-dependent math output |
| Constraint-based layout | Fixed geometry repeatedly conflicts with meaningful content | Optimize measurable fit with hard readability/semantic constraints; avoid solving the wrong inherited budgets |
| Authored templates with controlled parameters | Stable business forms, invoices, reports | Keep holdout templates/worlds separate; randomizing names alone is weak diversity |
| Public-data-backed synthetic reports | Plausibility and scientific/numeric relationships matter | Verify licensing and attribution; distinguish real observations from invented analysis |
| Independent native application exports | Single renderer fingerprints dominate | Real production paths cost more; metadata stamping is not a substitute |
| Browser/camera/print-scan capture | Synthetic blur/noise looks unlike target acquisitions | Record settings and rights; retain clean references and observable-content labels |
| Hybrid generated + permitted real corpus | Need external validity | Report domains separately; synthetic success alone cannot prove real-world transfer |
| Active coverage sampling | Many possible cases, limited review budget | Pick development gaps and disagreements; keep confirmation set untouched |
| Paired counterfactual documents | Need sensitive tests of factual extraction | Change one value/unit/order/qualifier with coherent downstream changes; use independent families for confirmation |

## Avoid the traps seen in long generation loops

- **Overconstrained cloning:** measuring source shape is useful; forcing its exact character counts onto different technical facts creates fake precision and endless exceptions. Preserve the extraction challenge, not incidental wording lengths.
- **Bulk before feasibility:** one beautiful page does not prove ten-page pagination, and hundreds of authored blocks do not prove any rendered fit. Run an end-to-end vertical slice early, including export and review.
- **One model as writer, calculator and judge:** use exact arithmetic, schema checks and independent review. Separate editorial judgment from rendered-label verification; disagreement should expose uncertainty.
- **Repeated committees without new evidence:** parallel reviews are useful when they inspect different dimensions or independently test a claim. Repeating the same textual debate cannot establish visibility. Run the missing physical control or narrow the claim.
- **Endless proof hardening:** a practical silver fixture can carry a documented precision limit. Reserve formal glyph/visibility proof for claims that require it; never falsely label the limited evidence exact.
- **Hidden infrastructure changes:** new fonts, exporters or normalizers invalidate relevant evidence. Pin dependencies and preserve failures, but distinguish semantic repeatability from byte repeatability when timestamps differ.
- **Renderer success mistaken for science:** an equation can look beautiful and be meaningless. Test why it belongs in the document, its variables/units, and the conclusion drawn from it.

## Minimal experiment record

Write the hypothesis, fixed semantic reference, compared paths, required structures, measured layout/quality outcomes, resource use and stopping rule. Save the actual outputs. Choose the least complex path that meets the contract; preserve the losing control and its limitation. Broaden only after the experiment answers the question.
