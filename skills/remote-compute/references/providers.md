# Provider discovery and adapters

Official documentation checked 2026-10-07. Recheck the chosen product, installed CLI version and region before operations. These links are discovery entry points, not maintained price quotes. API tokens usually authorize much more than a workload needs: keep provisioning/billing authority on the coordinator.

Environment names below are **project binding conventions** unless marked native. Confirm what the installed CLI actually reads; use protected config or subprocess environment, never token-valued command arguments. An adapter may map a project name to a provider-native name locally. Do not invent a balance endpoint or silently substitute another account.

Other candidates (Daytona/E2B sandboxes, Scaleway, Vultr, Beam, Together, Verda, Jarvislabs, CI/build services) fit the same contract. Look up official authentication, price, capability and teardown docs for the selected product; record custom key names as bindings rather than claiming native SDK support. Optional installed provider skills/connectors can supply mechanics; none is a dependency of this skill.

## A thin provider adapter contract

Implement only what the selected workload needs, using official interfaces. Agent-driven queries are sufficient for occasional runs; frequent runs benefit from a small versioned project adapter. Keep operations separate:

1. `identity`: verified account/project/region and permissions; secret presence is not authentication proof.
2. `quote`: offer/shape, whole allocation, currency, billing granularity/minimum term, availability, dated source, components and exclusions.
3. `inventory`: every relevant billable type, paginated to completion; known pre-existing and exact owned resources separate.
4. `billing`: credits, recent usage and time window with native semantics, timestamp, source, lag and coverage. Return unknown/unsupported honestly.
5. `create`: idempotency/run label plus exact ID receipt; reconcile uncertain responses before retrying.
6. `inspect` / `retire`: exact-ID state, provider action that ends charges, retained attachments, receipt and verification.

Persist only allowlisted normalized fields into the snapshot described in [monitoring](monitoring.md). Do not save raw responses containing tokens. Coordinate mutations and manifests with one writer or a lock; provider calls for independent read-only accounts may run concurrently. Do not claim a generic adapter or supervisor exists until its real implementation and cleanup path are verified.
