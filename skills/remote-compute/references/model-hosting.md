# Private model hosting

Use this when local Ollama, a desktop app, or another integrated client lacks RAM/VRAM, context capacity or throughput. First diagnose whether capacity, runtime/model compatibility, client configuration or network access is the actual problem. Offer a private hosted GPU as an option with a priced bounded pilot, not as an automatic repair.

Confirm the exact model identifier, publisher, license/access restrictions, weights format, supported runtime and required context/tool/structured-output features. Spoken model names may be ambiguous. Google's [Gemma documentation](https://ai.google.dev/gemma/docs) describes open model use, while [Gemini API models](https://ai.google.dev/gemini-api/docs/models) describe a hosted API; verify current distribution terms before promising downloadable Gemini weights or inventing a “Gemma Four” identifier. Check the installed [Ollama API/runtime](https://docs.ollama.com/) and any client's [OpenAI-compatible support](https://ollama.com/blog/openai-compatibility) rather than assuming every client can point to a remote server.

Choose capacity for weights **plus** runtime overhead, activation/workspace memory, KV cache at the requested context and concurrency, host RAM and model-download disk. VRAM is per device; host RAM is separate, and multi-GPU offers may require buying the whole allocation. Record quantization quality tradeoffs and compatibility. Do not silently lower context, output budget or model quality to make a cheap instance fit.

Choose a raw GPU host when OS/runtime control is necessary; consider a managed private endpoint when its engine, model, privacy and client interface fit. Serverless scale-to-zero can save idle compute but has cold starts and storage/warm-tail costs; verify actual product semantics. Price the complete replica including CPU/RAM and persistent storage, not just its GPU component.

Bind the model service to a private route, use an authenticated endpoint or coordinator SSH tunnel with forwarding restricted to the service, and check how the user's app accesses it. A desktop app may lack custom URL/auth settings; inspect documented integration options before renting. Keep the lifecycle key out of the app. Private deployment does not guarantee a provider never handles data: disclose verified tenancy/residency and relevant provider claims or unknowns in terms useful to the user.

Pin the publisher's compatible runtime/image recipe. Verify the real client request shape, largest representative context/output, streaming, tool/JSON behavior if needed, and sustained VRAM under expected parallelism. A tiny “hello” completion does not prove long-context readiness. Record throughput and revise cost/ETA after the pilot. Keep model artifacts/outputs off-host as required and retire the endpoint, replicas and billable storage under the normal ownership contract.
